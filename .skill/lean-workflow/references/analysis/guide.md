# Analysis formalization references

Choose the document matching the current obstacle; these are empirical lessons,
not extra skills or universal project policies. Verify Mathlib names against the
pinned dependency and measure performance hypotheses before restructuring code.

| Situation | Read |
|---|---|
| Choosing modules, imports, and namespaces | [Repository structure](references/repo_structure_policy.md) |
| Expensive carriers, instances, or dependent proofs | [Structured carriers](references/Lean4_EuclideanSpace_Elaboration_Guide.md) |
| Planning an analysis, PDE, or probability argument | [Analysis planning](references/dos_and_donts.md) |
| Constant dependencies, quantifiers, and Mathlib idioms | [Portable lessons](references/lean_learnings.md) |
| Variational PDE, multiscale, Besov, locality, or concentration | [Advanced patterns](references/advanced_analysis_patterns.md) |

Do not load all five documents for an ordinary Lean proof. Preserve mathematical
meaning when changing a representation; different carriers or bundled instances
can change both the statement and its elaboration cost.
